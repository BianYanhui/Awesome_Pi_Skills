# Handsoff

两个 Agent 交替做同一个仓库。`handsoff.md` 在仓库根目录。分隔线以上是固定说明，只在文件不存在时写一次。每次调用本 skill，只整段替换分隔线以下的内容。

## 每次调用

1. 确认当前目录是 git 仓库根。不是的话，先找到包含 `.git` 的根目录再写文件。
2. 若根目录没有 `handsoff.md`，用下面的固定说明新建，再写可变部分。
3. 若已有 `handsoff.md`，不要改、不要删、不要重排分隔线及以上的任何字，包括固定说明和 `---`。只替换 `---` 之后的全部内容，保留这一行分隔线。
4. 写之前先读分隔线下面的旧内容和它点名的路径。进程、端口、摘要文件以当时机器上的状态为准，不要凭对话记忆填写。
5. 写完后只提交 `handsoff.md`。不要把论文 PDF、原始结果目录或其他未要求的文件加进去。远程已配置时，把当前分支推上去，使这份交接和其他提交一样到远程。若推送还会带上别的未推送提交，先告诉用户，等用户同意再推。

固定说明里的「下一步」只在用户说「继续」时执行。用户没说继续，不要自己开长实验。

## 固定说明

新建文件时原样写入，不要改写成别的结构。

```markdown
# handsoff

本段到下面的分隔线为止是固定说明。后来的 Agent 不要改写、不要删、不要把当次进度写进这一段。每次交接只整段替换分隔线以下的内容。

## 这份文档是干什么的

同一个人会在两个 Agent 之间交替做这个仓库的开发。一边做完一段工作，就把分隔线下面更新掉；另一边先读这份文件，然后接着做，不用再口头补一大段上下文。

## 接手时

1. 先读分隔线下面的全文，再看它点名的文件和命令，不要凭记忆补实验设计。
2. 用户说「继续」时，按「下一步」做。没写进下一步的长实验不要自己开。
3. 改代码、跑实验、只查了状态，都算一段工作。离开前更新分隔线下面。

## 交接时怎么写

替换分隔线以下的全部内容，保留分隔线本身。写清这些，有代码 diff 就写，没有也要写：

- 现在在做哪件事，做到哪一步。
- 机器上还留着什么：进程、端口、GPU、容器、没跑完的队列。
- 已经定下来的结论和约束。不要只贴 git diff。
- 卡住的原因，以及下一次打开终端应该先跑的命令或先改的函数。
- 相关 commit、关键路径、明确不要提交或不要推送的文件。

不要把对话原文、完整 diff 或论文 PDF 贴进来。事实写短，路径写全。

---
```

## 可变部分写什么

分隔线以下用「可变交接」作标题。事实写短，路径写全。用用户正在用的语言。至少包括：

- 更新时间，以及现在在做哪件事、做到哪一步。
- 讨论过的方向和已经定下来的结论。不只记代码改动。
- 工作状态写明：还没开始、正在跑、已完成、失败后停着。正在跑要写 pid、启动命令、日志路径、进度（例如 21/40），以及不要再开一份、不要停掉哪个进程。
- 机器上还留着什么：进程、端口、GPU、容器。
- 下一步：用户说「继续」时做什么；没说就不要做的长实验。
- 已经定下来的约束，和明确不要提交、不要推送的文件。
- 相关 commit。有代码改动就点名文件和原因；没有也要写没有。

不要粘贴对话原文、完整 diff、论文 PDF。
